# หน้าจัดการสินค้า (Story 3)

ขั้นนี้ทำเฉพาะ **หน้าจัดการสินค้า (ระบบหลังบ้าน)** ตาม Story 3 ใน `AcceptanceCriteria.md` และ **ยังไม่ integrate API**

ก่อนเขียนโค้ด ให้อ่านและดูแหล่งต่อไปนี้อย่างละเอียด แล้วสรุปสั้นๆ ว่าหน้าจัดการจะประกอบด้วยอะไรบ้าง:

- `AcceptanceCriteria.md` — **Story 3 ทั้งหมด** (Header, ปุ่มสร้าง, ตาราง, Modal ฟอร์ม)
- `DefinitionOfDone.md` — เฉพาะส่วนที่เกี่ยวกับ validation ฟอร์ม (เช่น ชื่อซ้ำ, ราคาไม่สมเหตุสมผล)
- UI ของหน้าจัดการในโปรเจกต์ (mock, screenshot หรือไฟล์ออกแบบ)
- theme, UI component และ helper จากขั้นก่อน — **ใช้ซ้ำก่อน ห้ามสร้างใหม่โดยไม่จำเป็น**
- mock data จากขั้น 3–4 — **ใช้ชุดข้อมูลเดียวกันได้**

ถ้า UI หน้าจัดการไม่พบ หรือ AC กับ UI ขัดกัน หรือมีจุดที่ตีความได้มากกว่าหนึ่งแบบ ให้ถามก่อน ห้ามสมมติ layout หรือรายละเอียดที่ไม่มีในแหล่งเหล่านี้

## ขอบเขตที่ต้องทำ

ประกอบหน้าจัดการให้ครบตาม Story 3:

| ส่วน | ข้อกำหนดจาก AC |
| --- | --- |
| **Header** | หัวข้อ "ระบบจัดการสินค้า" ชัดเจนด้านบน |
| **ปุ่มสร้าง** | ปุ่ม `[ + สร้างรายการใหม่ ]` คลิกแล้วเปิด Modal |

## Responsive (ทำพร้อม UI ตั้งแต่ขั้นนี้)

DoD กำหนดว่า frontend ต้อง **Responsive** — อย่ารอไปทำทีหลัง

- ใช้ breakpoint จาก theme (ขั้น 2)
- **ตาราง:** scroll แนวนอนหรือปรับ layout บน mobile ให้ยังดูและกดแก้ไข/ลบได้
- **Modal ฟอร์ม:** ใช้งานได้บนจอเล็ก (เต็มจอหรือเกือบเต็มจอ), ช่องกรอกและปุ่มไม่ล้น
- ปุ่มสร้างรายการและหัวข้อยังอ่านและกดได้บน mobile

## Logic (ยังไม่ต่อ API)

- ใช้ **mock data / state ใน memory** แทนการเรียก API
- ทำ CRUD บน state ในเครื่อง: สร้าง, แก้ไข, ลบ แล้่งานสะท้อนในตารางทันที
- เปิด Modal สร้าง (ฟอร์มว่าง) และ Modal แก้ไข (prefill จากแถวที่เลือก)
- ปุ่ม `[ ยกเลิก ]` ปิด Modal โดยไม่บันทึก
- อัปโหลดรูปทำ preview ฝั่ง client (เช่น `URL.createObjectURL`) ยังไม่ส่งไฟ backend
- จำกัดรูปรถไม่เกิน 4 รูป และรองรับเฉพาะ `.png`, `.jpg`
- ทำ **validation ฝั่ง client** ตาม DoD ที่เกี่ยวกับฟอร์ม เช่น ชื่อซ้ำ, ราคาติดลบหรือเกิน `99999999`, ช่องที่จำเป็นต้องกรอก
- **เชื่อมปุ่ม "จัดการสินค้า" จากหน้าแรก** ให้มาหน้านี้ได้

## สิ่งที่ห้ามทำ

- ห้ามเรียก API หรือเชื่อม backend
- ห้ามสร้าง theme / component / helper ใหม่ ถ้ามีของเดิมใช้ได้แล้ว

## หลังทำเสร็จ

สรุปสั้นๆ ครอบคลุม:

1. ไฟล์ที่สร้างหรือแก้ไข
2. แต่ละส่วน UI อ้างอิงข้อ AC ข้อใด
3. CRUD และ Modal ทำงานอย่างไร
4. validation และการจัดการรูปทำงานอย่างไร
5. responsive แต่ละ breakpoint ทำงานอย่างไร

หากมีสิ่งใดไม่ชัดเจนหรือมีคำถาม ให้ถามฉันก่อนดำเนินการเสมอ
