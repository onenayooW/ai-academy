# หน้าแรก (Story 1)

ขั้นนี้ทำเฉพาะ **หน้าแรก (หน้ารวมสินค้า)** ตาม Story 1 ใน `AcceptanceCriteria.md` ยังไม่ทำ Story 2, Story 3 และ **ยังไม่ integrate API**

ก่อนเขียนโค้ด ให้อ่านและดูแหล่งต่อไปนี้อย่างละเอียด แล้วสรุปสั้นๆ ว่าหน้าแรกจะประกอบด้วยอะไรบ้าง:

- `AcceptanceCriteria.md` — **Story 1 ทั้งหมด** (Header, Grid, Card, ปุ่มติดต่อ, Filter)
- UI ของหน้าแรกในโปรเจกต์ (mock, screenshot หรือไฟล์ออกแบบ)
- theme, UI component และ helper ที่สร้างไว้แล้วจากขั้นก่อน — **ใช้ซ้ำก่อน ห้ามสร้างใหม่โดยไม่จำเป็น**

ถ้า UI หน้าแรกไม่พบ หรือ AC กับ UI ขัดกัน หรือมีจุดที่ตีความได้มากกว่าหนึ่งแบบ ให้ถามก่อน ห้ามสมมติ layout หรือรายละเอียดที่ไม่มีในแหล่งเหล่านี้

## ขอบเขตที่ต้องทำ

ประกอบหน้าแรกให้ครบตาม Story 1:

| ส่วน | ข้อกำหนดจาก AC |
| --- | --- |
| **Header** | โลโก้ "Truck2Hand" มุมซ้ายบน, ปุ่ม "จัดการสินค้า" มุมขวาบน (ลิงก์ไปหน้าหลังบ้าน) |
| **Grid** | แสดงรายการรถเป็น Grid 3–4 กล่องต่อแถว |
| **Card** | รูปใหญ่ด้านบน, ชื่อรถ, ยี่ห้อ \| รุ่น \| ปี (ตัวเล็กสีเทา), ราคา (ตัวใหญ่สีแดง), รูปโปรไฟล์ผู้ขาย + ชื่อ + ป้ายเขียว "ผู้ขายยืนยันตัวตน" |
| **Call to action** | มุมขวาล่างของ Card มี Icon Line และโทรศัพท์ คลิกติดต่อได้ |
| **Filter** | กรองได้จาก ประเภทรถ, ช่วงราคา, ช่วงปี, ยี่ห้อ และ รุ่น |

## Responsive (ทำพร้อม UI ตั้งแต่ขั้นนี้)

DoD กำหนดว่า frontend ต้อง **Responsive** — อย่ารอไปทำทีหลัง

- ใช้ breakpoint จาก theme (ขั้น 2)
- **Grid:** desktop 3–4 กล่องต่อแถว, tablet/mobile ลดจำนวนคอลัมน์ตาม design system
- **Header:** โลโก้และปุ่มจัดการสินค้ายังใช้งานได้บนจอเล็ก
- **Filter:** จัดเรียงให้ใช้งานได้บน mobile (เช่น stack แนวตั้ง)
- **Card:** เนื้อหาและปุ่มติดต่อไม่ล้นหรือทับกันบนจอเล็ก

## Logic (ยังไม่ต่อ API)

- ใช้ **mock data** ในโปรเจกต์ (เช่น ไฟล์ static หรือ constant) แทนการเรียก API
- ทำ logic กรองบน mock data ให้กรองหลายเงื่อนไขพร้อมกันได้
- ปุ่ม Line / โทรศัพท์ ใช้ข้อมูลจาก mock data (เช่น `tel:` หรือลิงก์ Line)
- ปุ่ม "จัดการสินค้า" ตั้ง route ไปหน้าหลังบ้านได้ แต่ยังไม่ต้องทำหน้านั้น (placeholder ได้)
- คลิก Card เพื่อไปหน้ารายละเอียดยังไม่ต้องทำใน step นี้ เว้นแต่ route placeholder จำเป็นต่อโครงสร้าง router

## สิ่งที่ห้ามทำ

- ห้ามเรียก API หรือเชื่อม backend
- ห้ามทำ Story 2 (หน้ารายละเอียด) และ Story 3 (หน้าจัดการสินค้า)
- ห้ามสร้าง theme / component / helper ใหม่ ถ้ามีของเดิมจากขั้น 2 ใช้ได้แล้ว

## หลังทำเสร็จ

สรุปสั้นๆ ครอบคลุม:

1. ไฟล์ที่สร้างหรือแก้ไข
2. แต่ละส่วน UI อ้างอิงข้อ AC ข้อใด
3. mock data อยู่ที่ไหน และ filter ทำงานอย่างไร
4. responsive แต่ละ breakpoint ทำงานอย่างไร

หากมีสิ่งใดไม่ชัดเจนหรือมีคำถาม ให้ถามฉันก่อนดำเนินการเสมอ
