# Theme, UI components, and helpers

Do not build pages in this step. Create only the project theme, reusable UI components, and helper functions.

Before writing any code, read and review all of the following, then briefly summarize what you will create:

- `AcceptanceCriteria.md` — screens, UI pieces, and required behavior
- `DefinitionOfDone.md` — frontend requirements only
- UI in the project (mock, screenshot, or design file)
- Design system in the project (color, typography, spacing, and components)

If the UI or design system is missing, or anything can be interpreted in more than one way, ask first. Do not invent colors, sizes, or components that are not in these sources, and do not create files until you have an answer.

Ask only what is necessary, such as where the design system lives and which components the AC requires but the design system does not include.

Once the sources are complete and clear, create only these three parts inside the existing frontend project:

1. **Project theme** — design tokens (color, typography, spacing, radius, **breakpoints**) that match the design system and can be reused across the app
2. **UI components** — only the pieces the AC requires, styled strictly from the design system, not assembled into pages — **every component must be responsive from the start**, using breakpoints from the theme
3. **Helper functions** — functions the screens will need from the AC and DoD, such as price and vehicle-meta formatting, contact links, and image and price checks. Do not add functions the spec does not use

DoD requires the frontend to be **responsive** — do not defer this. Set up breakpoints and components for mobile/tablet/desktop in this step.

Afterward, briefly summarize which files you created, which AC item each one supports, and which breakpoints you used.

If anything is unclear or you have any questions, always ask me before proceeding.
