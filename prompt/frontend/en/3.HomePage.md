# Home page (Story 1)

Build only the **home page (product listing)** per Story 1 in `AcceptanceCriteria.md`. Do not build Story 2 or Story 3, and **do not integrate the API yet**.

Before writing any code, read and review the following in detail, then briefly summarize what the home page will include:

- `AcceptanceCriteria.md` — **all of Story 1** (Header, Grid, Card, contact buttons, Filter)
- Home page UI in the project (mock, screenshot, or design file)
- Theme, UI components, and helpers from the previous step — **reuse them first; do not recreate unless necessary**

If the home page UI is missing, AC and UI conflict, or anything can be interpreted in more than one way, ask first. Do not invent layout or details that are not in these sources.

## Scope

Assemble the home page to match Story 1:

| Section | AC requirement |
| --- | --- |
| **Header** | "Truck2Hand" logo top-left, "จัดการสินค้า" button top-right (links to admin) |
| **Grid** | Product grid with 3–4 cards per row |
| **Card** | Large image on top, vehicle name, brand \| model \| year (small gray text), price (large red), seller avatar + name + green badge "ผู้ขายยืนยันตัวตน" |
| **Call to action** | Line and phone icons bottom-right of each card, clickable to contact |
| **Filter** | Filter by vehicle type, price range, registration year range, brand, and model |

## Responsive (build with UI in this step)

DoD requires the frontend to be **responsive** — do not defer this.

- Use breakpoints from the theme (step 2)
- **Grid:** 3–4 cards per row on desktop; fewer columns on tablet/mobile per design system
- **Header:** logo and admin button remain usable on small screens
- **Filter:** usable on mobile (e.g. stacked vertically)
- **Card:** content and contact buttons do not overflow or overlap on small screens

## Logic (no API yet)

- Use **mock data** in the project (e.g. a static file or constants) instead of calling the API
- Implement filter logic on mock data; multiple filters must work together
- Line / phone buttons use mock data (e.g. `tel:` or Line link)
- "จัดการสินค้า" can route to the admin page, but that page does not need to be built yet (placeholder is fine)
- Card click to product detail is out of scope for this step unless a router placeholder is required

## Do not

- Call the API or connect to the backend
- Build Story 2 (product detail) or Story 3 (admin)
- Create new theme / components / helpers if existing ones from step 2 already cover the need
