# ออกแบบฐานข้อมูล

ใช้เฉพาะเอกสารต่อไปนี้:

- `AcceptanceCriteria.md`
- `DefinitionOfDone.md`

ออกแบบ schema ฐานข้อมูลโดยไม่ใช้ข้อมูลจากเอกสารอื่น และไม่สมมติฟีเจอร์ที่ไม่ได้ระบุไว้ชัดเจน

## Tech stack

หากระบุใน DoD ให้ใช้ดังนี้:

| ชั้น | ตัวเลือก |
| --- | --- |
| Database | SQLite |
| ORM | drizzle-orm |
| Driver | better-sqlite3 |

ใช้ชื่อชนิดข้อมูล SQLite ในเอกสาร (เช่น `INTEGER`, `TEXT`)

## ข้อกำหนดผลลัพธ์

- บันทึกไฟล์ไปที่: `[path, e.g. /project/docs/DB]`
- หนึ่งตารางต่อหนึ่งไฟล์ `.md`
- ชื่อไฟล์ต้องเป็นชื่อตารางแบบ `snake_case` (เช่น `products.md`)

ใช้รูปแบบต่อไปนี้สำหรับแต่ละไฟล์:

```markdown
# Table Name: {table_name}

Description: {อธิบายเป็นภาษาไทยว่าตารางเก็บอะไร และหน้า/ฟีเจอร์ใดใช้งาน}

Source: [ลิงก์และข้อความอ้างอิงสั้นๆ จากสเปก]

## Fields

| Field Name | Required | Data Type | Description | Example |
| --- | --- | --- | --- | --- |
| ... | Yes/No | INTEGER/TEXT/... | ... | ... |
```

หากตารางมี constraint, index หรือค่า seed ที่จำเป็น ให้เพิ่มหลังตาราง Fields เช่น:

- **Constraint:** `UNIQUE(...)`
- **Required initial values:** (สำหรับ master tables)

## กฎการออกแบบ

- แยก master/lookup tables ออกจาก transactional tables ให้ชัดเจน
- สำหรับ foreign key ให้ระบุความสัมพันธ์ใน Description ด้วยรูปแบบ: `FK → other_table.id`
- หากสเปกขัดแย้งหรือไม่ชัดเจน—เช่น filter อ้างถึงฟิลด์ที่ไม่มีในฟอร์ม—ให้ถามฉันก่อนดำเนินการ ห้ามสมมติเอง

## หลังออกแบบเสร็จ

สรุปสั้นๆ ครอบคลุม:

1. รายชื่อตาราง
2. ความสัมพันธ์ foreign key
3. ลำดับการ insert ที่ไม่ละเมิด foreign key constraint

หากมีสิ่งใดไม่ชัดเจนหรือมีคำถาม ให้ถามฉันก่อนดำเนินการเสมอ
