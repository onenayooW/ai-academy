# Create Unit Test

**ทำหลัง:** `4.Implement.md` (ต้องมี `backend/` และรันได้แล้ว)

**ยังไม่ทำในรอบนี้:** seed CSV ใน `docs/DataExample/` (`6.SeedData.md`) — test ต้องใช้ `:memory:` + setup ใน test ไม่พึ่งไฟล์ seed จริง

เขียน unit / integration tests สำหรับ backend Truck2Hand ให้ครบตาม docs และ DoD
Frontend ไม่ทำ

## แหล่งความจริง

1. Contract: `docs/API/*.md` (status, body, validation)
2. Validation: blocklist → `backend/src/config/blocklist.ts`
3. โค้ดและ convention ที่มีอยู่:
   - vitest: `npm test` / `npm run test:watch`
   - HTTP tests: `backend/src/test-app.ts` → `createTestApp()` (SQLite `:memory:`, temp uploads, seed catalog + admin + seller)
   - ตัวอย่าง: `products.test.ts`, `auth.test.ts`, `app.test.ts`, `blocklist.test.ts`

## Tech

- vitest 3.x, Node fetch กับ `app.listen(0)` บน `127.0.0.1`
- `BCRYPT_ROUNDS=4` ใน test-app (เร็วขึ้น)
- อัปโหลดรูปใน test: `PNG_1X1` จาก test-app + FormData + Blob

## ประเภท test ที่ต้องมี

A) Integration (HTTP) — ใช้ `createTestApp()` หรือ pattern เดียวกัน
   - `beforeAll`: createTestApp, login เก็บ token ตาม role
   - `afterAll`: `close()` ลบ server + sqlite + uploads temp
   - helper: `authHeaders()`, `createProduct()`, `postJson()`

B) Pure unit — ไม่ต้องเปิด server
   - blocklist, seed builder, parse/validation helpers
   - ทด edge case ชัดเจน (substring vs whole word ฯลฯ)

## สิ่งที่ต้อง cover (ตาม DoD + docs)

Catalog:
- GET vehicle-types, brands, models?brand_id=

Products:
- POST สร้างสำเร็จ, GET list paginate + filter AND + sort (newest, price_asc/desc, most_viewed)
- 409 ชื่อซ้ำ (รวม trim/case ถ้า implement แบบนั้น)
- 400 ราคา, FK, model/brand mismatch, blocklist
- GET by id เพิ่ม view_count; PUT ไม่เพิ่ม view_count
- DELETE 404 / 200 + GET หลังลบเป็น 404

Product images:
- POST สูงสุด 4, รูปแรกเป็นปก
- PATCH cover, DELETE แล้วปก/ sort_order ถูกต้อง
- 400 ครบ 4 รูป / 404 ไม่มี product

Health / docs (ถ้ามี `app.test.ts`):
- GET `/health`
- ไม่ต้อง test Swagger UI ลึก ๆ

Seed builder ในโค้ด (ถ้ามี เช่น `seed-products.ts`):
- `buildSeedProducts`: จำนวน, unique title, FK, price/year range, รูป 1–3 ต่อ product, is_cover
- ยังไม่เกี่ยวกับ `docs/DataExample/*.csv` — นั้นเป็นขั้นถัดไป

## กฎการเขียน

- describe/it ชื่ออ่านเป็น spec ได้
- assert status ก่อน แล้วค่อย assert body สำคัญ
- ไม่พึ่ง `docs/DataExample` หรือ `backend/data/app.db` จริง — ใช้ `:memory:` + setup ใน test
- test แยกไฟล์ตาม domain (`*.test.ts` คู่ src/)
- ไม่ mock ทั้ง stack ถ้า integration เร็วพอ; mock เฉพาะ external (เช่น download รูป seed) ถ้าจำเป็น

## ส่งงาน

- รายการไฟล์ test ที่เพิ่ม/แก้
- ตารางสั้น: Test file → สิ่งที่ cover
- ช่องว่างที่ยังไม่ cover (ถ้ามี) + เหตุผล

หากมีสิ่งใดไม่ชัดเจนหรือมีคำถาม ให้ถามฉันก่อนดำเนินการเสมอ
