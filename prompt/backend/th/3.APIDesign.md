# ออกแบบ API

ใช้เฉพาะเอกสารความต้องการต่อไปนี้ในการออกแบบ REST API

ห้ามใช้ข้อมูลจากเอกสารอื่น หรือสมมติ endpoint ที่สเปกไม่รองรับ

## แหล่งความต้องการ

ใช้เฉพาะ:

- `AcceptanceCriteria.md`
- `DefinitionOfDone.md`

## อ้างอิง schema

หากมีอยู่แล้ว:

- `[path, e.g. /project/docs/DB]` — endpoint ต้องสอดคล้องกับตารางและความสัมพันธ์ foreign key
- ห้ามออกแบบ response ที่ขัดกับ `docs/DB` โดยไม่ถามฉันก่อน

## Tech stack

หากระบุใน DoD:

| รายการ | ค่า |
| --- | --- |
| Backend | Node.js + Express |
| อัปโหลดไฟล์ | multer (`.png`, `.jpg`) |
| ตัวอย่าง Base URL | `http://localhost:8080` |
| คำนำหน้า path | `/v1/api/...` |

## ข้อกำหนดผลลัพธ์

- บันทึกไฟล์ไปที่: `[path, e.g. /project/docs/API]`
- จัดกลุ่มไฟล์ตาม resource และ endpoint
- หนึ่ง endpoint ต่อหนึ่งไฟล์
- ใช้คำนำหน้า operation เช่น `{retrieve,create,update,delete}_...` และนามสกุล `.md`

### โครงสร้างไฟล์

แต่ละไฟล์ operation ควรตามโครงสร้างนี้ (คั่นแต่ละ operation ด้วย `---` หากหลาย operation อยู่ในไฟล์เดียว):

**Base Endpoint:** `http://localhost:8080`

**Auth** (หาก login หรือ role อยู่ในขอบเขต):

- ระบุความต้องการ Bearer token และอ้างอิง `docs/API/authorization.md` หรืออธิบาย role ที่อนุญาตต่อ endpoint
- หาก authentication อยู่นอกขอบเขต ให้ละส่วนนี้

**Validation / business rules** (เฉพาะ resource นั้น):

- HTTP status ที่คาดหวัง เช่น `400`, `404`, `409`
- กฎใน DoD เช่น ชื่อซ้ำ ราคา blocklist จำนวนรูปสูงสุด เป็นต้น

**เทมเพลตบล็อก operation:**

```markdown
{OPERATION_NAME_IN_UPPER_SNAKE_CASE}: {คำอธิบายสั้นเป็นภาษาไทยว่าหน้า/ฟีเจอร์ใดใช้ operation นี้}

Method: GET | POST | PUT | PATCH | DELETE
Path: `/v1/api/...`

Path Params:

| Field | Type | Description |
| --- | --- | --- |
| ... | ... | ... |

หากไม่มี path parameter: `Path Params: -`

Query Params:

| Field | Type | Description | Default |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

หากไม่มี query parameter: `Query Params: -`

Request Body (ถ้ามี):

- สำหรับ `application/json` ใช้ตาราง Field, Type, Description
- สำหรับ `multipart/form-data` ใช้ตาราง Field, Type, Description โดยใช้ `File` เป็นชนิดข้อมูลของรูป

Response Body:

- ใช้ตาราง Field, Type, Description สำหรับ nested records
- สำหรับรายการแบบแบ่งหน้า ให้มี `page`, `size`, `total`, `items`
- หาก response มี nested record objects ให้เขียนแยกใต้หัวข้อ **Record Object (...)** แต่ละอัน

Error Handling (เมื่อมีหลายกรณี):

| HTTP | When |
| --- | --- |
| ... | ... |
```

หากมีสิ่งใดไม่ชัดเจนหรือมีคำถาม ให้ถามฉันก่อนดำเนินการเสมอ
