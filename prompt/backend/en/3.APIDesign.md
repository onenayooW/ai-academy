# Design API

**After:** `2.DesignDatabase.md`

Use only the following requirement documents when designing the REST API.

Do not use information from other documents, or assume endpoints the spec does not support.

## Requirement sources

Use only:

- `AcceptanceCriteria.md`
- `DefinitionOfDone.md`

## Tech stack

If specified in the DoD:

| Item | Value |
| --- | --- |
| Backend | Node.js + Express |
| File upload | multer (`.png`, `.jpg`) |
| Example Base URL | `http://localhost:8080` |
| Path prefix | `/v1/api/...` |

## Output requirements

- Save files to: `docs/API`
- Group files by resource and endpoint
- One endpoint per file
- Use operation prefixes such as `{retrieve,create,update,delete}_...` and the `.md` suffix

### File structure

Each operation file should follow this structure (separate multiple operations in one file with `---`):

**Base Endpoint:** `http://localhost:8080`

**Validation / business rules** (for that resource only):

- Expected HTTP statuses, e.g. `400`, `404`, `409`
- DoD rules such as duplicate names, price blocklist, max image count, etc.

**Operation block template:**

```markdown
{OPERATION_NAME_IN_UPPER_SNAKE_CASE}: {Short description of which page/feature uses this operation}

Method: GET | POST | PUT | PATCH | DELETE
Path: `/v1/api/...`

Path Params:

| Field | Type | Description |
| --- | --- | --- |
| ... | ... | ... |

If there are no path parameters: `Path Params: -`

Query Params:

| Field | Type | Description | Default |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

If there are no query parameters: `Query Params: -`

Request Body (if any):

- For `application/json`, use Field, Type, Description tables
- For `multipart/form-data`, use Field, Type, Description tables; use `File` as the type for images

Response Body:

- Use Field, Type, Description tables for nested records
- For paginated lists, include `page`, `size`, `total`, `items`
- If the response has nested record objects, document each under **Record Object (...)** headings

Error Handling (when there are multiple cases):

| HTTP | When |
| --- | --- |
| ... | ... |
```

If anything is unclear or you have questions, ask me before proceeding.
