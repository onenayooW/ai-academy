# Design Database

**After:** `1.SetUpProject.md`

Use only the following documents:

- `AcceptanceCriteria.md`
- `DefinitionOfDone.md`

Design the database schema without using information from other documents, and do not assume features that are not explicitly specified.

## Tech stack

If specified in the DoD, use:

| Layer | Choice |
| --- | --- |
| Database | SQLite |
| ORM | drizzle-orm |
| Driver | better-sqlite3 |

Use SQLite data type names in the documentation (e.g. `INTEGER`, `TEXT`).

## Output requirements

- Save files to: `docs/DB`
- One table per `.md` file
- File names must be the table name in `snake_case` (e.g. `products.md`)

Use the following format for each file:

```markdown
# Table Name: {table_name}

Description: {Describe what the table stores and which pages/features use it}

Source: [Short link and reference text from the spec]

## Fields

| Field Name | Required | Data Type | Description | Example |
| --- | --- | --- | --- | --- |
| ... | Yes/No | INTEGER/TEXT/... | ... | ... |
```

If a table needs constraints, indexes, or required seed values, add them after the Fields table, for example:

- **Constraint:** `UNIQUE(...)`
- **Required initial values:** (for master tables)

## Design rules

- Clearly separate master/lookup tables from transactional tables
- For foreign keys, document the relationship in Description using: `FK → other_table.id`
- If the spec is conflicting or unclear—e.g. a filter references a field not on the form—ask me before proceeding; do not assume

## After design is complete

Provide a short summary covering:

1. List of tables
2. Foreign key relationships
3. Insert order that does not violate foreign key constraints

If anything is unclear or you have questions, ask me before proceeding.
